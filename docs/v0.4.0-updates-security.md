# 签名更新与最小权限

根因：HTTPS 元数据未单独签名，攻击者可能把较高版本与旧有效签名包配对。采用官方 tauri-plugin-updater >= 2.14.1 的 requireSignedVersion，默认版本比较且 allowDowngrades=false；官方插件核验包签名与可信注释中的版本。下载前额外限制为本 fork 的 HTTPS 发布资产。没有公钥时不发起网络更新请求、不允许安装。

主界面启动时自动检查一次，关于页提供手动检查和确认后安装。Rust 保存待安装的 Update 对象，只接受确认时的版本，不从 WebView 接收 URL、公钥或文件路径。单操作原子锁避免重复下载/检查。远程更新说明仅通过 textContent 呈现，最多 4000 字符，避免超大 UI 内容。

WebView 仅开放必要的应用命令、事件订阅/取消订阅及版本读取；不开放通用插件 IPC、事件 emit 或远程能力。构建 manifest 与能力名单由静态安全检查校验。开发 CI 在解析实际锁文件后运行 RustSec，正式发布使用严格锁定及同一审计。审计发现漏洞不静默忽略。

正式发布需有效公开密钥和私钥 Secret，标签须等于应用版本；官方 Tauri CLI 2.12+ 将签名绑定版本。CI 仅在正式标签构建时启用 createUpdaterArtifacts；所有平台测试、构建与清单完整性检查成功后才公开草稿。清单检查不是密码学验证，实际安装由官方 updater 强制验签。Windows MSI、macOS app、Linux AppImage 为自动更新目标。系统代码签名/公证独立处理。

本次不生成私钥、不修改 Actions Secrets、不创建标签和 Release、不合并 main；签名端到端测试需真实密钥及测试安装包。新增 updater 依赖需要 CI 产出锁文件并恢复严格锁定。既有校园网探测及 Portal 兼容性问题不在本次范围。
