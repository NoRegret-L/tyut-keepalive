# 暂停、休眠及网络变化恢复

- 根因：单纯定时检查在网络变化和唤醒后可能仍持有旧任务与长退避。使用 netwatcher 原生网络接口回调（不轮询）与社区 tauri-plugin-power-monitor 电源事件；均从 Rust 后台进入同一调度器，隐藏窗口也能处理。
- 归纳约束：用户暂停、系统休眠、密码拒绝是独立的禁止自动认证条件；保存/清除凭据不解除用户暂停，唤醒不解除用户暂停或密码拒绝。只有明确手动重连可以重试被拒绝的凭据。暂停仅在本次应用进程内有效，不主动注销网络。
- 闭环：触发变化时撤销旧任务代次，等待其返回后才派发一个新检测；先检测可达性，再沿用原有重试机制。使用原有退避参数；不新增自定义防抖时间阈值。接口回调只传递变化信号，最多一个待处理网络事件，待处理的立即检查合并重复变化。
- 已发出的 HTTP 请求不能撤回；取消标记在原有认证阶段检查，旧代次结果不会修改新状态。接口地址/名称不写入日志或传输给前端。
- 休眠、暂停、网络接口变化结束不确定的在线观测区间，不虚构中断次数。日志记录系统事件类型，托盘和前端共享 Rust 状态。
- 兼容性：netwatcher 监听初始化失败时保留原有周期检查；Linux 休眠事件依赖 systemd-logind，非 logind 环境可能无法收到。原生事件与系统托盘需 Windows、Linux、macOS 实机验证；不承诺所有同 IP 路由变化均能感知。
- 新增依赖需 CI 生成真实 Cargo.lock，提交后恢复严格锁定；发布检查从不允许自动更新锁文件。
